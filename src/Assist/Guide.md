# PropFind – Project Guide

## Overview

**PropFind** is a static, client-side property listing platform built with plain HTML, CSS, and JavaScript (no framework, no build step). It simulates India's smart property discovery experience — letting users search, filter, compare, and enquire about properties across major cities.

All data is mocked in `js/properties.js` and persisted client-side via `localStorage` (authentication state, favourites, dashboard listings).

## Data Model

Each property in `PROPERTIES` (defined in `js/properties.js`) carries the following shape:

```js
{
  id, title, location, city, pincode,
  price, priceLabel, purpose,          // "Rent" | "Buy" | "Lease"
  type, bhk, area, furnishing,
  floor, balcony, parking, petFriendly,
  powerBackup, wifi, water, cctv, gated,
  availableFrom, verified,
  images[],
  amenities[],
  nearby: { schools[], hospitals[], metro[], supermarkets[] },
  lat, lng,                             // used by map-view.html
  rating, reviews                       // used by property-detail.html
}
```

## Authentication Model

`Auth` is a global helper (inlined in `js/properties.js` or individual pages) that wraps `localStorage`:

| Method | Purpose |
|---|---|
| `Auth.register(name, email, username, password)` | Create a new account |
| `Auth.login(username, password)` | Validate and persist session |
| `Auth.logout()` | Clear session |
| `Auth.getCurrentUser()` | Return the logged-in user object or `null` |
| `Auth.toggleFavorite(id)` | Add/remove a property ID from the user's favourites |
| `Auth.isFavorite(id)` | Check if a property is favourited |

A built-in demo account (`username: demo`, `password: demo123`) is pre-seeded.

## QA Automation

### Test Case Definitions
All test cases are defined in `Assist/Rearranged_testcases.xlsx`. Each row captures:
- **TC ID** – unique identifier (e.g. TC01)
- **User Story** – parent feature (e.g. US01)
- **Test Scenario** – one-line description
- **Test Steps** – numbered action sequence
- **Expected Result** – pass criteria
- **Classification** – Functional / Negative / Validation / Performance
- **Priority** – High / Medium / Low

### Selenium Test Architecture
The automation follows the **Page Object Model (POM)** pattern:

```
BaseTest (WebDriver setup/teardown)
    └── <PageName>Test  (TestNG @Test methods)
            └── <PageName>Page  (element locators + action methods)
```

**Key conventions:**
- Locators use `By.id` exclusively where possible (all interactive elements carry stable `id` attributes)
- `WebDriverWait` with a 10-second timeout guards every interaction
- No `driver.findElement` calls inside test methods — all access via the Page Object
- `@Test` annotations include `testName="TCXX"` and `groups={"USXX", "Classification", "Priority"}`
- `@DataProvider` handles multi-row scenario outlines

### Generating New Tests
The file `Assist/GENERATE_TESTS.md` is a structured prompt guide for AI-assisted test generation. To generate your assigned tests:
1. Open a new AI chat session and type `@src\Assist\GENERATE_TESTS.md`
2. When prompted, type your **first name** (e.g. `Raman`, `Prabavathi`)
3. The assistant looks up your assigned TC IDs from `Assist/TEAM_ASSIGNMENTS.md`, reads the xlsx, identifies the HTML page, extracts element IDs, and produces all three artefacts:
   - `src/Assist/features/<Page>.feature` — Gherkin BDD scenarios
   - `src/test/java/pages/<Page>Page.java` — Page Object class
   - `src/test/java/tests/<Page>Test.java` — TestNG test class

## Running the Project

Because the project is fully static, no build or server is required for manual testing:

1. Open any `.html` file directly in Chrome.
2. For Selenium tests, ensure `chromedriver` is on your `PATH` and matches your installed Chrome version.
3. Run `mvn test` — the Surefire plugin picks up `src/test/test.xml` automatically.
   The `baseUrl` resolves itself to the `TargetWebsite` folder bundled inside the project,
   so **no path editing is needed**. If you want to test against a different location,
   add a `<parameter name="baseUrl" value="file:///your/path/"/>` line to `test.xml`.
